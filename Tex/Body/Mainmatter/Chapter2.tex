\chapter{Theoretical Background}

\section{Cryptographic Handshake Protocols}

A cryptographic handshake is a process by which two parties establish a shared secret over an insecure communication channel. This shared secret can then be used for symmetric encryption of subsequent communications. The security of modern internet protocols like TLS (Transport Layer Security) relies fundamentally on robust handshake mechanisms.

\subsection{Key Exchange Fundamentals}

The challenge of key exchange was solved by Diffie and Hellman in 1976 \cite{Diffie1976}, introducing the concept of public-key cryptography. In a typical key exchange protocol:

\begin{enumerate}
\item Each party generates a public-private key pair
\item Public keys are exchanged over the insecure channel
\item Each party uses their private key and the other's public key to derive a shared secret
\item The shared secret is identical for both parties without ever being transmitted
\end{enumerate}

This process provides forward secrecy—even if long-term keys are later compromised, past session keys remain secure.

\section{Elliptic Curve Cryptography}

Elliptic Curve Cryptography (ECC) offers equivalent security to RSA with significantly smaller key sizes. The use of elliptic curves in cryptography was independently proposed by Miller \cite{Miller1985} and Koblitz \cite{Koblitz1987}. An elliptic curve over a finite field is defined by the equation:

\[y^2 = x^3 + ax + b \pmod{p}\]

where $p$ is a large prime number, and $a, b$ are curve parameters satisfying $4a^3 + 27b^2 \neq 0$.

\subsection{The secp256k1 Curve}

This project implements the secp256k1 curve, which is widely used in Bitcoin and other cryptocurrencies \cite{SEC2}. The curve parameters are:
\begin{itemize}
\item Prime: $p = 2^{256} - 2^{32} - 977$
\item Curve coefficients: $a = 0, b = 7$ (making the equation $y^2 = x^3 + 7$)
\item Generator point $G$ with order $n$
\end{itemize}

\subsection{ECDH Key Exchange}

Elliptic Curve Diffie-Hellman (ECDH) works as follows:

\begin{enumerate}
\item Alice generates private key $d_A$ (random integer) and computes public key $Q_A = d_A \cdot G$
\item Bob generates private key $d_B$ and computes public key $Q_B = d_B \cdot G$  
\item Alice and Bob exchange public keys
\item Both compute the shared secret: $S = d_A \cdot Q_B = d_B \cdot Q_A = d_A d_B \cdot G$
\end{enumerate}

The security relies on the Elliptic Curve Discrete Logarithm Problem (ECDLP)—given $Q$ and $G$, it is computationally infeasible to find $d$ such that $Q = d \cdot G$.

\section{The Quantum Threat}

While classical cryptographic systems like RSA and ECC have secured communications for decades, the development of large-scale quantum computers poses a fundamental threat to these algorithms, making post-quantum cryptography an urgent priority.

\subsection{Shor's Algorithm and the Quantum Threat}

In 1994, Peter Shor developed a quantum algorithm that efficiently solves both integer factorization and discrete logarithm problems—the mathematical foundations of RSA and ECC security \cite{Shor1997}. By exploiting quantum superposition and entanglement, Shor's algorithm can break these cryptosystems in polynomial time, whereas classical computers require exponential time \cite{Nielsen2010}.

Though large-scale quantum computers do not yet exist, the "harvest now, decrypt later" threat—where adversaries collect encrypted data today to decrypt once quantum computers are available—demands immediate action to protect long-term sensitive data \cite{Mosca2018}.

\subsection{Quantum Key Distribution}

Quantum Key Distribution (QKD) offers information-theoretic security by using quantum mechanics principles to detect eavesdropping during key exchange \cite{Bennett1984}. However, QKD faces critical practical limitations: it requires expensive specialized hardware, is limited to distances under 200 kilometers, provides only point-to-point communication, requires separate authentication mechanisms, and cannot perform digital signatures or other public-key operations \cite{Diamanti2016}.

Most importantly, QKD is not a drop-in replacement for existing public-key infrastructure. In contrast, post-quantum algorithms like CRYSTALS-Kyber can be deployed as software updates over existing networks, providing comprehensive cryptographic services while maintaining compatibility with current protocols \cite{NIST-PQC}.

\section{Post-Quantum Cryptography: CRYSTALS-Kyber}

CRYSTALS-Kyber is a Key Encapsulation Mechanism (KEM) based on the Module Learning With Errors (Module-LWE) problem, which is believed to be secure against quantum attacks \cite{Peikert2016}. Unlike traditional key exchange where both parties contribute to the shared secret, a KEM works asymmetrically:

\begin{enumerate}
\item The receiver generates a public-private key pair
\item The sender uses the public key to encapsulate a random session key, producing a ciphertext
\item The sender transmits the ciphertext
\item The receiver decapsulates using their private key to recover the session key
\end{enumerate}

\subsection{Lattice-Based Cryptography}

Kyber belongs to the family of lattice-based cryptographic algorithms, which represent the leading approach to post-quantum security. A lattice $\mathcal{L}$ in $n$-dimensional space is a discrete subgroup that can be represented as all integer linear combinations of basis vectors:

\[\mathcal{L} = \left\{\sum_{i=1}^{n} a_i \mathbf{v}_i : a_i \in \mathbb{Z}\right\}\]

where $\mathbf{v}_1, \ldots, \mathbf{v}_n$ form the lattice basis. Geometrically, lattices can be visualized as regular grids of points extending infinitely in all directions \cite{Micciancio2009}.

A crucial insight in lattice cryptography is that different basis representations of the same lattice can have vastly different properties. Figure~\ref{fig:lattice_basis} illustrates this concept: a ``good basis'' consists of short, nearly orthogonal vectors that clearly reveal the lattice structure, while a ``bad basis'' consists of long, highly skewed vectors that obscure it. Cryptographic security relies on publishing only a bad basis—the trapdoor is knowledge of the good basis.

\begin{figure}[htbp]
\centering
\includegraphics[width=0.95\textwidth]{lattice_good_vs_bad_basis.png}
\caption{Good basis versus bad basis representations. Both generate identical lattice points, but the bad basis makes geometric problems much harder in high dimensions.}
\label{fig:lattice_basis}
\end{figure}

The security of lattice-based cryptography relies on computationally hard problems in lattices:

\textbf{Shortest Vector Problem (SVP):} Given a lattice basis, find the shortest non-zero vector in the lattice.

\textbf{Closest Vector Problem (CVP):} Given a lattice and a target point, find the lattice point closest to the target.

Figure~\ref{fig:svp_cvp} visualizes these problems. SVP requires finding the closest non-zero lattice point to the origin, while CVP generalizes this to finding the closest lattice point to any arbitrary target. Both problems become exponentially harder as the dimension $n$ increases.

\begin{figure}[htbp]
\centering
\includegraphics[width=0.95\textwidth]{lattice_svp_cvp.png}
\caption{The Shortest Vector Problem (SVP) and Closest Vector Problem (CVP). SVP finds the shortest non-zero vector from the origin; CVP finds the lattice point nearest to an arbitrary target point.}
\label{fig:svp_cvp}
\end{figure}

These problems remain hard even for quantum computers. While Shor's algorithm efficiently breaks RSA and ECC, no comparable quantum algorithm exists for lattice problems \cite{Regev2009}. The reason of this quantum resistance is the geometric nature of lattices. Quantum computers excel at exploiting algebraic structures (like the cyclic groups used in RSA/ECC), but lattice problems lack the periodic structure that quantum algorithms can exploit.

\subsection{Standardization of Lattice-Based Cryptography}

In July 2022, NIST selected CRYSTALS-Kyber as the primary standard for post-quantum key encapsulation, alongside CRYSTALS-Dilithium for digital signatures \cite{NIST-Selection}. Lattice-based schemes held a clear edge over competitors—comprising three of the four initial algorithms—reflects their favorable balance between quantum security and practical performance.

Beyond theoretical hardness, lattice schemes offer operational characteristics suitable for general-purpose deployment. Unlike code-based systems (e.g., Classic McEliece), which require public keys in the megabyte range, or isogeny-based schemes which have high computational requirements, lattice schemes maintain relatively small key sizes and fast execution times \cite{Bernstein2017}.

While other families were standardized for specific use cases, the combination of manageable key sizes and performance efficiency makes lattice-based cryptography the primary candidate for current public-key infrastructure.


\subsection{Mathematical Foundation: Module-LWE}

The security of Kyber is based on the hardness of the Module Learning With Errors (Module-LWE) problem, which is a structured variant of the Learning With Errors (LWE) problem introduced by Regev \cite{Regev2005}. The LWE problem is directly related to lattices—specifically, it can be viewed as a bounded-distance decoding problem on random lattices.

Given a matrix $\mathbf{A}$ of polynomials and a vector $\mathbf{b} = \mathbf{A} \cdot \mathbf{s} + \mathbf{e}$, where $\mathbf{s}$ is a secret and $\mathbf{e}$ is small error (noise), it is computationally hard to recover $\mathbf{s}$ even with a quantum computer. The noise term $\mathbf{e}$ represents intentional errors that obscure the algebraic structure, converting what would be a simple linear algebra problem into a lattice problem.

The "Module" variant uses structured polynomial rings instead of arbitrary matrices, reason being using polynomials allows us to represent high dimensional lattice structures more efficiently while maintaining security through proper parameter selection. While Regev established the hardness of standard LWE \cite{Regev2009}, the hardness of Module-LWE reduces to solving worst-case lattice problems, meaning an attacker who can break Module-LWE could also solve previously mentioned lattice problems \cite{Langlois2015}.

\subsection{Polynomial Rings}

Kyber operates in the polynomial ring $R_q = \mathbb{Z}_q[X]/(X^{256} + 1)$, where:
\begin{itemize}
\item $q = 3329$ is the modulus
\item Polynomials have degree at most 255
\item Coefficients are reduced modulo $q$
\item Multiplication is performed modulo $X^{256} + 1$
\end{itemize}

This ring structure allows using Number Theoretic Transform (NTT), which reduces the complexity of polynomial multiplication.

\subsection{Key Generation, Encapsulation, and Decapsulation}

The Kyber algorithm implements a Key Encapsulation Mechanism (KEM) through three main operations. The security of these operations relies on the hardness of the Module-LWE problem, where small random errors obscure the underlying algebraic structure \cite{NIST-Selection}.

\textbf{Key Generation:} The receiver generates a key pair by first sampling a public random matrix $\mathbf{A} \in R_q^{k \times k}$ and a secret vector $\mathbf{s}$ with small coefficients. The secret vector $\mathbf{s}$ is chosen from a distribution with small values to ensure security while maintaining correctness. An error vector $\mathbf{e}$ with similarly small coefficients is also sampled. The public key is then computed as $\mathbf{t} = \mathbf{A} \cdot \mathbf{s} + \mathbf{e}$, where the error term $\mathbf{e}$ provides the Module-LWE hardness. The public key consists of $(\mathbf{A}, \mathbf{t})$ while $\mathbf{s}$ remains the secret key.

\textbf{Encapsulation:} To establish a shared secret, the sender uses the receiver's public key $(\mathbf{A}, \mathbf{t})$ to encapsulate a randomly chosen message $m$. The sender samples their own secret vector $\mathbf{r}$ and error terms $\mathbf{e}_1, e_2$, all with small coefficients. The ciphertext is computed as $\mathbf{u} = \mathbf{A}^T \cdot \mathbf{r} + \mathbf{e}_1$ and $v = \mathbf{t}^T \cdot \mathbf{r} + e_2 + \text{Encode}(m)$, where $\text{Encode}$ maps the message to a suitable representation in the polynomial ring. The ciphertext $(\mathbf{u}, v)$ is sent to the receiver, and both parties derive the same shared secret from the message $m$ through a key derivation function.

\textbf{Decapsulation:} The receiver uses their secret key $\mathbf{s}$ to recover the message by computing $m' = \text{Decode}(v - \mathbf{s}^T \cdot \mathbf{u})$. The subtraction $v - \mathbf{s}^T \cdot \mathbf{u}$ cancels out most terms, leaving primarily the encoded message plus small error terms. If the errors are sufficiently small (which the parameter selection ensures), the $\text{Decode}$ function correctly recovers $m$, allowing the receiver to derive the same shared secret \cite{Peikert2016}. The accumulated errors from key generation and encapsulation must remain below a threshold for correct decryption, which is guaranteed by Kyber's parameter choices with overwhelming probability.

\section{Security Parameters and Variants}

Both ECC and post-quantum algorithms offer multiple security levels to balance security requirements with performance. Security levels are measured in bits of security, representing the computational effort required to break the cryptosystem. NIST defines security strength categories that provide a standardized way to compare cryptographic algorithms across different families \cite{NISTSP800-57,NIST-PQC-Levels}.

NIST's post-quantum cryptography standardization process explicitly defines security levels 1, 3, and 5, corresponding to the computational resources required to break AES-128, AES-192, and AES-256 respectively \cite{NIST-PQC-Levels}. Common security levels and their implementations:
\begin{itemize}
\item \textbf{128-bit security (NIST Level 1):} Kyber-512 ($k=2$), secp256k1/secp256r1 (256-bit ECC), comparable to AES-128
\item \textbf{192-bit security (NIST Level 3):} Kyber-768 ($k=3$), secp384r1 (384-bit ECC), comparable to AES-192
\item \textbf{256-bit security (NIST Level 5):} Kyber-1024 ($k=4$), secp521r1 (521-bit ECC), comparable to AES-256
\end{itemize}

The Kyber specification defines these parameter sets to target specific NIST security levels \cite{Kyber-Spec}, while NIST SP 800-57 provides equivalent security strength comparisons for ECC key sizes relative to symmetric algorithms \cite{NISTSP800-57}.

While ECC and Kyber provide comparable security against classical attacks, Kyber maintains its security in the post-quantum era, whereas ECC is vulnerable to Shor's algorithm \cite{Shor1997}. Other standardized curves exist (e.g., secp192r1, secp224r1) but are less commonly deployed \cite{SEC1}. This project implements secp256k1 and Kyber variants, using kyber-512 as the default, both providing 128-bit security with Kyber offering quantum resistance.
